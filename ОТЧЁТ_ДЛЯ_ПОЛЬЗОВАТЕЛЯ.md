## ЧТО БЫЛО СЛОМАНО

### Проблема

API импорта (`/api/seed-code-blocks`) читал весь HTML-файл целиком и сохранял его в поле `html`, оставляя поля `css` и `javascript` пустыми:

```typescript
// БЫЛО (неправильно):
const rawContent = readFileSync('preview/employees.html', 'utf-8');

await supabase.from('code_blocks').insert({
  html: rawContent,  // ← весь файл (20,000 символов)
  css: '',           // ← пусто
  javascript: ''     // ← пусто
});
```

### Результат теста (ДО исправления)

Вы запустили http://localhost:3000/test-import.html и увидели:

```
✅ API вернул успешный ответ:
   employees.html: htmlLength=9551, cssLength=10931, jsLength=0

❌ Но в базе данных:
   HTML = 0 символов
   CSS = 0 символов
   JavaScript = 0 символов
```

**Причина:** API правильно парсил файлы, но **не мог записать в БД** из-за Row Level Security (RLS).

## ЧТО ИСПРАВЛЕНО

### 1. Добавлен парсер HTML/CSS/JavaScript ✅

**Файл:** `app/api/seed-code-blocks/route.ts`

Теперь API использует функцию `parseCodeBlockSource()`, которая:
- Извлекает `<style>...</style>` → поле `css`
- Извлекает `<script>...</script>` → поле `javascript`
- Оставляет чистый HTML без `<style>` и `<script>` → поле `html`
- Извлекает external dependencies (`<script src>`, `<link>`) → поле `dependencies`

```typescript
// СТАЛО (правильно):
const rawContent = readFileSync('preview/employees.html', 'utf-8');
const parsed = parseCodeBlockSource(rawContent);

await supabase.from('code_blocks').insert({
  html: parsed.html,             // ← только HTML (9,551 символов)
  css: parsed.css,               // ← только CSS (10,931 символов)
  javascript: parsed.javascript, // ← только JavaScript (0 для employees.html)
  dependencies: parsed.dependencies
});
```

---

### 2. Добавлен admin client для обхода RLS ✅

**Файл:** `lib/supabase/admin.ts` (новый)

Создана функция `createAdminClient()`, которая использует **service_role key** вместо обычного **anon key**:

```typescript
import { createClient } from '@supabase/supabase-js';

export function createAdminClient() {
  const supabaseUrl = process.env.NEXT_PUBLIC_SUPABASE_URL;
  const serviceRoleKey = process.env.SUPABASE_SERVICE_ROLE_KEY; // ← новая переменная

  return createClient(supabaseUrl, serviceRoleKey, {
    auth: { persistSession: false }
  });
}
```

**Результат:** API теперь может записывать данные в таблицу `code_blocks`, минуя RLS.

---

### 3. Импорт больше не удаляет существующие блоки ✅

**Было:**
```typescript
// Удаляло ВСЕ блоки перед импортом
await supabase.from('code_blocks').delete().neq('id', '00000000-0000-0000-0000-000000000000');
```

**Стало:**
```typescript
// Использует upsert по slug
await supabase.from('code_blocks').upsert(rows, {
  onConflict: 'slug'
});
```

**Результат:** Импорт обновляет существующие preview-блоки, не трогая пользовательские блоки.
